# 콜드메일·DM 글쓰기 규칙

실제 영업 담당자의 피드백을 수십 회 반영해 확정한 규칙이다. 제품·SaaS·출강/컨설팅과 상관없이 적용한다.
사용자 본인의 말투 프로필이 있으면 어조는 그쪽을 따르고, 구조·문형·흐름은 이 문서를 따른다.

## 1. 구조 (메일)

```
안녕하세요. {회사} 담당자님,
{발신 소개 한 줄}

{연락 이유 한 줄}                         ← 관측된 신호(채용·문의·검토·발주·투자·세미나)
{상황}하시는 만큼, 혹시 ~지는 않으신가요?   ← 질문 훅 1개 (앞 문장과 자연스러운 인과 연결)

{제품/서비스 소개 한 문장}                ← 상황별로 다르게, 짧게 (재접근은 생략)
{제품/과정}을 진행/사용하시게 되면, ~할 수 있습니다.  ← 질문에 직접 답하는 첫 번째 결과
또한, ~할 수 있습니다.                    ← 두 번째 이득 또는 상황별 추가 구성 1개

{회신 요청 한 줄}

감사합니다.
{이름} 드림
```

- 문장마다 줄을 바꾸고, 문단 사이는 빈 줄 하나.
- 본문(인사·서명 제외)은 공백 제외 150~350자.
- 제목: `[{발신 회사/이름}] {회사}_{제품/제안} 안내의 건_{YYMMDD}` (과감한 카피 제목·느낌표 금지).

## 2. 구조 (DM — 카카오·인스타·링크드인)

- 300자 이내, 4~5줄. **이메일 문장을 그대로 잘라 붙이지 않는다.**
- **호칭**: 링크드인처럼 상대 이름을 알면 `{이름}님` (`contact_name` 열 사용), 모를 때만 `{회사} 담당자님`.
- **말투**: `"회신 부탁드립니다"`, `"~으로 안내해 드리겠습니다"` 같은 공문서·콜센터 말투 대신 `"편하게 답장 주세요"`, `"~사례를 공유해 드리겠습니다"`처럼 자연스러운 메신저 어조를 쓴다.
- **질문은 전체 DM에서 최대 1개**만 둔다(질문 2개 연달아 금지).
- 제품 소개 문장과 "또한," 문장은 뺀다.

## 3. 신호 강도별 2트랙 작법 (근거 없는 억지 질문 방지)

| 신호 강도 | 언제 쓰나 | 흐름 |
|---|---|---|
| **트랙 A (강한 신호)** | 구체적 채용 공고·링크드인 글·나라장터 발주·세미나 등 직접 근거가 있을 때 | 관측 사실 1줄 → 그 사실에서 자연스럽게 나오는 질문 훅 1개 → 구체적 결과 → 사례·자료 공유 |
| **트랙 B (약한 신호)** | 단순 직함·홈페이지 소개 등 근거가 얕을 때 | 억지 `"~하시는 만큼, 혹시 ~?"`를 **빼고**, 업종 접점 1줄 → 실제로 푸는 구체 작업 1줄 → 참고 사례 공유 |

## 4. 문형·구체성 규칙

| 규칙 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|
| 자기소개 | "~ 담당자 {이름}입니다." / "제조·유통 기업 AI 실무 워크숍을 진행하는 {이름}입니다." | "~을 맡고 있는", "~을 안내하고 있습니다" |
| 질문 훅 | "~하시는 만큼, 혹시 ~지는 않으신가요?" / "~계신가요?" (강한 신호일 때만) | "~않나요?"(버릇없음), "여전히", "아직도", 근거 없는 "~하시는 만큼," |
| 짐작 | 질문으로 바꿈 | "~것 같았습니다", "~기 쉽습니다"(훈수), 상대 업종을 상대에게 설명하는 투 |
| 이득과 리듬 | 구체적 작업명 1개 이상 포함(예: 보고서 초안, 엑셀 정리, CS 요약). 필요 시 `"~진행해서, 당일 ~를 바로 가져가시는 방식입니다"`처럼 설명서체 완화 | `"~하시게 되면, ~하실 수 있습니다"` 3회 이상 기계 연타, 추상어(`결과물`, `효율화`, `구성`)만 나열 |
| 쉼표·"~수 있습니다" | 사용자가 의도한 호흡 쉼표(`~하시는 만큼,`, `또한,`), `~할 수 있습니다` 유지(사용자 말투) | `korean-humanizer`가 기계적으로 쉼표를 지운 결과를 그대로 쓰지 않는다 |
| 회신 요청 (CTA) | "관심이 있으시면 편하게 답장/회신 주세요. 비슷한 {업종} 기업 사례와 커리큘럼을 공유해 드리겠습니다." | "~모습을 보여드리겠습니다", "~방식으로 안내해 드리겠습니다"(콜센터체) |
| 상대 회사 정보 | 확인된 사실만 짧게 녹임 | "~하고 계셨습니다", 모르는 내부 상황을 이미 아는 척하는 표현 |

## 5. 문장 간 연결·인과/흐름 규칙 (Coherence & Causal Flow)

`korean-humanizer`로 다듬을 때도 아래 4단 인과 흐름이 끊기지 않게 유지한다.

1. **근거 → 질문 (비약 금지)**: 첫 줄의 사실(채용·발주·투자·세미나)이 둘째 줄 `~하시는 만큼,`의 직접 원인이어야 한다. 근거가 약하면 트랙 B로 전환해 억지 질문을 뺀다.
2. **질문 → 이득 (직접 응답 + 구체 장면)**: 질문 훅에서 던진 고민을 바로 받아 답하되, 추상어 대신 실제 작업명(보고서 초안, 엑셀 정리, CS 요약 등)을 최소 1개 넣는다.
3. **소개 ↔ 이득 (중복 금지)**: 소개 문장과 바로 뒤 이득 문장이 같은 말을 되풀이하면 둘 중 하나를 고친다.
4. **이득 → CTA (자연스러운 착지)**: 앞 문장에서 꺼낸 주제와 CTA가 1:1로 이어지게 쓰며, 모르는 상대 회사에 억지 "맞춤 안내"를 약속하지 않고 검증된 유사 사례·자료 공유로 착지한다.

## 6. 높임 주어 규칙

- 상대 회사 사람이 하는 행동 → "~하실": "콜백 목록을 보고 다시 연락하실 수 있습니다."
- 발신자(나)가 하는 행동 → "~드리다": "연락드립니다", "안내해 드리겠습니다."
- 제품·챗봇이 상대의 고객에게 하는 일 → "답해 드릴 수 있습니다" 허용.
- 틀린 예: "통화 중에 온 전화는 콜백 목록에 남아 순서대로 다시 연락드릴 수 있습니다." (주어가 상대인데 겸양)

## 7. 제품·서비스 소개 문장

- 처음 연락하는 곳에는 제품·서비스가 무엇인지 한 문장을 꼭 넣는다(재접근 고객은 생략).
- 상황별로 다르게: 반복 문의형 / AI·매뉴얼형 / 관리자·대규모형 / 실무 워크숍형 / 리더십 특강형 등.
- 길게 쓰지 않는다(공백 포함 60자 안팎). 기능·커리큘럼 전부를 넣지 않는다.

## 8. 내용·근거 규칙

- 신호(채용·투자·문의·공고)는 구매 의사의 증거가 아니다. 단정하지 않는다.
- **수신자별 신뢰 근거 1:1 매칭 (Proof-to-Buyer Fit)**: 강사·발신자 이력을 한꺼번에 나열하지 않고, **해당 수신자·공고 주제에 가장 신빙성 있는 이력 1~2개만** 골라 쓴다.
  - 예: AI 에이전트·자동화 담당자 → 실제 에이전트·자동화 구축 및 실습 진행 이력 / 비개발 실무·대학·공공 교육 담당자 → 비기술 직군 코칭·워크숍 만족도·수강 인원 이력 / 제조·의료 도메인 교육 → 해당 도메인 실무 프로젝트 이력.
  - **공식 출강 vs 커뮤니티·공간 대관 행사 구분**: 커뮤니티 세미나나 특정 기업 오피스를 대관해 열린 비공식 행사는 장소 회사명을 내세워 마치 해당 기업 공식 출강·파트너인 것처럼 오해받게 쓰지 않는다.
- 모든 개인화 문장은 **근거 원문 URL(`evidence_url`)**과 연결해 사람이 10초 안에 교차검증할 수 있어야 한다.
- 사례는 회사명 없이 업종·규모로만. 계약 금액은 쓰지 않는다.
- 확인 안 된 기능·가격·수치·일정은 쓰지 않는다(`[확인 필요]`로 남긴다).
- 경쟁사보다 싸다, AI 정확도 비교, 이관 일정 약속은 쓰지 않는다.
- 다른 부서가 담당하는 제품·범위 밖 건은 제안하지 않고 '담당 부서 전달 대상'으로 표시한다.
- 자리표시(`[회사명]` 등)가 남은 초안을 내보내지 않는다.

## 9. 법·연락처 규칙 (국내, 법률 자문 아님)

- 광고성 메일: 제목 `(광고)` 표기, 수신거부 방법, 사전 동의 규정(정보통신망법 제50조)을 발송 전에 확인.
- 홈페이지에서 프로그램으로 이메일 주소를 자동 수집하지 않는다(제50조의2). 이메일이 적힌 페이지 주소만 남긴다.
- 채용 공고의 지원용 이메일을 영업에 쓰지 않는다.
- 전화·카카오 채널·톡톡·인스타·문의 페이지 같은 공개 창구는 모아도 된다.
- 초안까지만 만든다. 발송은 사람이 한다.

## 10. 자체 점검

- [ ] "않나요?", "같았습니다", "여전히", "모습을 보여드리", em-dash(`—`) 0건
- [ ] 자리표시 0건, 따옴표·괄호 깨짐 0건
- [ ] 높임 주어 오류 0건("다시 연락드릴 수 있습니다" 등)
- [ ] 근거 → 질문 → 이득 → CTA 인과 흐름이 자연스럽고 소개↔이득 중복 없음
- [ ] 근거 원문 URL(`evidence_url`)을 열어 사실 일치 여부 확인 완료
- [ ] 확인 안 된 사실 없음
