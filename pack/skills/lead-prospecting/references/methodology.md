# B2B 리드 발굴 5단계 방법론

> 이 문서는 `lead-prospecting` 스킬의 상세 프로세스 참고서다.
> 각 단계의 실행 원칙, 판단 기준, 주의사항을 정의한다.

---

## 개요

B2B 리드 발굴은 "누가 살 가능성이 높은가"를 공개 정보만으로 추론하는 과정이다.
핵심 원리: **이미 산 사람의 주변을 본다.**
솔루션을 도입한 회사(케이스스터디)는 직접 리드가 아니라 **레퍼런스 지도**다. 그 주변의 경쟁사와 생태계 기업이 실제 타깃이다.

---

## 1단계: 도입사 발굴 — 솔루션 케이스스터디 수집

### 목적
자사 솔루션 또는 경쟁 솔루션을 실제로 도입한 회사 목록을 확보한다.
이 목록은 영업 레퍼런스 풀이자, 리드 확장의 출발점이다.

### 실행 원칙
1. **케이스스터디 페이지를 최우선 소스로 삼는다.**
   - 자사 웹사이트: 고객 사례, 파트너 사례, 블로그 성공 사례
   - 경쟁사 웹사이트: 동일 위치의 페이지
   - G2, Capterra 등 리뷰 플랫폼의 리뷰어 회사명
2. **각 도입사에 대해 최소한 다음을 기록한다:**
   - 회사명, 업종, 규모(직원 수·매출 — 공개 정보 기준)
   - 도입한 솔루션명
   - 도입 목적 또는 해결한 문제 (케이스스터디 원문 기준)
   - 케이스스터디 URL과 게시 날짜
3. **없는 정보는 빈칸으로 둔다.** 추측으로 채우지 않는다.

### 주의사항
- 케이스스터디에 명시되지 않은 수치(절감액, 효율 향상 %)를 재인용할 때 수치를 변형하지 않는다.
- 도입사 목록을 콜드아웃리치 대상으로 쓰지 않는다. 이미 고객이거나 경쟁사 고객이므로 직접 영업 대상이 아니다.

### 산출물
| 도입사명 | 업종 | 규모 | 도입 솔루션 | 주요 도입 목적 | 케이스스터디 URL | 날짜 |
|----------|------|------|-------------|----------------|-----------------|------|
| (예시)   |      |      |             |                |                 |      |

## 2단계: 리드 확장 — 경쟁사·생태계 기업 파악

### 목적
1단계 도입사 각각에서 출발해, 아직 솔루션을 도입하지 않은 유사 기업을 신규 리드 후보로 발굴한다.

### 실행 원칙
1. **직접 경쟁사 파악:**
   - 도입사와 동일 업종·유사 규모의 회사를 웹 검색, LinkedIn, 업종 DB에서 찾는다.
   - "A사의 경쟁사는?" 키워드로 검색하거나, A사 직원의 이전 직장(LinkedIn)을 탐색한다.
2. **생태계 니치 파악:**
   - 도입사와 같은 공급망, 파트너 네트워크, 고객군에 속한 기업을 파악한다.
   - 예: 도입사가 물류사라면 → 동일 노선의 다른 물류사, 물류 소프트웨어 연계 기업.
3. **레퍼런스 레버 가능성 메모:**
   - 도입사와 후보 기업 간의 관계(경쟁, 파트너, 공급망 등)를 명시한다.
   - "A사가 도입했다"는 사실을 영업 대화에서 어떻게 활용할 수 있는지 한 줄 메모.

### 주의사항
- 이 단계에서 BANT는 평가하지 않는다. 후보 목록만 만든다.
- 확인되지 않은 경쟁 관계를 사실처럼 기재하지 않는다.

### 산출물
| 후보사명 | 업종 | 규모 | 기준 도입사 | 관계 | 레퍼런스 활용 가능성 |
|----------|------|------|------------|------|---------------------|
| (예시)   |      |      |            |      |                     |

## 3단계: 적합 리드 선별 — 자사 강점 매칭

### 목적
2단계 후보 중 자사 솔루션의 강점이 실제로 맞아떨어지는 회사를 추린다.

### 실행 원칙
1. **자사 강점 목록을 먼저 정의한다** (이 스킬을 사용하는 시점에 사용자가 제공하거나 wiki에서 로드).
   - 예: 빠른 구현 속도, 중소기업 특화 가격, 특정 업종 레퍼런스 다수, API 유연성 등.
2. **각 후보사의 특징과 대조한다:**
   - 공개된 이슈(뉴스, 채용 공고, 대표자 인터뷰)
   - 현재 사용 도구(LinkedIn, 잡 포스팅에서 파악 가능한 경우)
   - 업종·규모 특성
3. **강점 매칭이 2개 이상인 후보만 다음 단계로 진행한다.**
   - 매칭 항목과 그 근거(출처)를 `lead-profile.md`에 기재한다.
4. **매칭 점수가 낮은 후보는 '보류' 처리하고 이유를 기재한다.** 삭제하지 않는다.

### 주의사항
- "왠지 잘 맞을 것 같다"는 직관만으로 선별하지 않는다. 반드시 외부 정보 근거가 있어야 한다.
- 강점 목록을 미리 정의하지 않으면 이 단계가 주관적 판단으로 흐른다. 정의 먼저.

### 산출물
선별 통과 리드마다 `templates/lead-profile.md` 하나를 작성한다.

## 4단계: BANT 및 시그널 평가

### 목적
선별 리드를 외부 공개 정보 기반으로 BANT 평가해 우선순위를 산정한다.

### 실행 원칙
1. **각 항목을 1~5점으로 평가한다.** 시그널 사전은 `references/bant-signals.md` 참조.
2. **근거 없는 점수는 주지 않는다.** 정보가 없으면 '추가 조사 필요'로 표시한다.
3. **`scripts/lead_scorer.py`로 가중 합산 점수를 계산한다:**
   - Budget(B): 30%
   - Authority(A): 25%
   - Need(N): 30%
   - Timeline(T): 15%
   - 시그널 보너스: +10% (해당 시 적용)
4. **최종 등급 기준:**
   - **고(高)**: 70점 이상 → 즉시 제안 단계 진입
   - **중(中)**: 40~69점 → 추가 조사 후 재평가
   - **저(低)**: 40점 미만 → 보류

### 주의사항
- 콜드아웃리치 이전이므로 직접 연락해서 정보를 얻으면 안 된다. 공개 정보만.
- Budget 시그널이 없다고 0점을 주면 안 된다. '추가 조사 필요'가 맞는 처리다.

### 산출물
선별 리드마다 `templates/bant-evaluation.md` 하나 + `lead_scorer.py` 출력값.

## 5단계: 맞춤제안 작성

### 목적
BANT 평가에서 '고' 등급을 받은 리드에게 보낼 맞춤형 제안서 개요를 작성한다.

### 실행 원칙
1. **`templates/proposal-outline.md` 구조를 그대로 따른다.**
2. **고객 이해 섹션은 3~4단계에서 수집한 외부 정보만으로 작성한다.**
3. **페인포인트는 공개 정보(뉴스, 채용 공고, 대표 인터뷰)에서 직접 추출한다.** 추측을 섞지 않는다.
4. **레퍼런스 섹션에는 1단계에서 확인한 케이스스터디를 인용한다** — URL과 수치 원문 포함.
5. **기대효과 수치는 인용이거나 보수적 추산임을 명시한다.** 근거 없이 "XX% 절감"을 쓰지 않는다.
6. **CTA는 단계적으로 설정한다:** 전화 미팅 요청 또는 PoC 제안 — 즉시 계약 요청 금지.

### 주의사항
- 제안서에서 고객을 과도하게 칭찬하는 마케팅 문체는 피한다. 사실 기반의 평이한 문체로 작성한다.
- 고객사 내부 사정(미확인 예산, 담당자 실명 등)을 확인한 것처럼 쓰지 않는다.

### 산출물
`templates/proposal-outline.md`를 채운 최종 제안 개요 문서.

## 단계별 체크리스트 요약

| 단계 | 핵심 질문 | 완료 기준 |
|------|-----------|-----------|
| 1. 도입사 발굴 | 누가 이미 샀는가? | 도입사 목록 + 케이스스터디 URL |
| 2. 리드 확장 | 도입사 주변에 누가 있는가? | 경쟁사·생태계 후보 목록 |
| 3. 강점 매칭 | 우리가 더 잘 맞는 곳은? | lead-profile.md (매칭 2건 이상) |
| 4. BANT 평가 | 살 준비가 되어 있는가? | bant-evaluation.md + 점수/등급 |
| 5. 맞춤제안 | 어떻게 설득할 것인가? | proposal-outline.md 완성 |
