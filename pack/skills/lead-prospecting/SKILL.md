# B2B 리드 발굴 자동화 (lead-prospecting)

**한 줄 요약:** 솔루션 도입 사례에서 출발해 경쟁사·생태계 리드를 확장하고, 외부 공개 정보만으로 BANT 평가 후 맞춤제안까지 완성하는 5단계 파이프라인.

---

## 워크플로 (5단계)

> 전체 상세 프로세스는 `${HERMES_SKILL_DIR}/references/methodology.md` 참조.
> BANT 시그널 사전은 `${HERMES_SKILL_DIR}/references/bant-signals.md` 참조.

### 1단계 — 도입사 발굴 (솔루션 케이스스터디)
**목적:** 자사 솔루션 또는 경쟁 솔루션을 이미 도입한 회사 목록 확보.

**실행 지침:**
- 자사·경쟁사 웹사이트의 고객 사례(케이스스터디, 고객 후기, 파트너 페이지)를 크롤링한다.
- 도입 업종·규모·적용 영역을 함께 기록한다.
- 이미 도입한 회사는 **직접 리드가 아니라 레퍼런스 소스**로 분류한다.

**도구:** `web-reader` 스킬, Hermes 기본 웹 검색, 수동 케이스스터디 페이지 열람.

**산출물:** 도입사 목록 (회사명, 업종, 규모, 도입 솔루션, 케이스스터디 URL).

---

### 2단계 — 리드 확장 (경쟁사·생태계)
**목적:** 1단계 도입사의 직접 경쟁사 또는 같은 생태계의 니치 기업을 신규 리드 후보로 확장.

**실행 지침:**
- 도입사 각각에 대해 동일 업종·유사 규모의 경쟁사를 파악한다.
- 동일 공급망·파트너 생태계에 속한 기업도 후보에 포함한다.
- 레퍼런스(도입사)를 영업 레버로 쓸 수 있는 관계인지 확인한다.
- 이 단계에서 검증하지 않은 수치나 관계는 기록하지 않는다.

**도구:** Hermes 기본 웹 검색, `web-reader`, LinkedIn 공개 페이지, 업종 DB (공개 자료만).

**산출물:** 확장 리드 후보 목록 (도입사 → 연결 경쟁사/생태계 기업, 관계 설명).

---

### 3단계 — 적합 리드 선별 (자사 강점 매칭)
**목적:** 후보 중 자사 솔루션의 강점이 가장 잘 맞는 고객사를 추린다.

**실행 지침:**
- 자사 솔루션의 핵심 강점 목록과 각 후보의 특징(업종, 규모, 현재 도구, 공개된 이슈)을 대조한다.
- 강점이 2개 이상 매칭되는 회사를 우선순위 후보로 선정한다.
- 매칭 근거는 반드시 외부 공개 정보 출처와 함께 기록한다.
- 근거 없이 "잘 맞을 것 같다"는 추측으로 선별하지 않는다.

**도구:** `templates/lead-profile.md` 작성.

**산출물:** 선별 리드 프로필 (각 회사당 `templates/lead-profile.md` 하나).

---

### 4단계 — BANT 및 시그널 평가
**목적:** 선별 리드를 외부 공개 정보 기반으로 BANT(Budget·Authority·Need·Timeline) 평가.

**실행 지침:**
- BANT 각 항목을 1~5점으로 평가한다. 근거는 출처 URL·날짜와 함께 기록한다.
- 정보가 없는 항목은 점수를 추측하지 않고 **'추가 조사 필요'**로 표시한다.
- `scripts/lead_scorer.py`로 가중 합산 점수를 계산한다 (B 30%, A 25%, N 30%, T 15%).
- 추가 시그널(채용 공고, 투자유치, 시설 확장 등)이 있으면 +10% 보너스 적용.
- 최종 등급: **고(70점 이상) / 중(40~69점) / 저(40점 미만)**.

**도구:** `templates/bant-evaluation.md`, `scripts/lead_scorer.py`.

**산출물:** BANT 평가 시트 + 우선순위 점수 + 등급.

```bash
# BANT 점수 계산 예시
python3 ${HERMES_SKILL_DIR}/scripts/lead_scorer.py --b 4 --a 3 --n 5 --t 2 --signal 1
# 출력: 가중 점수, 등급(고/중/저)
```

---

### 5단계 — 맞춤제안 작성
**목적:** 최종 선별 리드에게 보낼 맞춤형 제안서(개요) 작성.

**실행 지침:**
- `templates/proposal-outline.md`의 구조를 따른다.
- 고객 이해 → 페인포인트 → 해법 → 레퍼런스 → 적용 계획 → 기대효과 → CTA 순서.
- 기대효과에 포함하는 수치는 반드시 외부 공개 출처 기반이어야 한다. 근거 없는 수치 날조 금지.
- 레퍼런스(도입사)는 1단계에서 확인한 케이스스터디 URL을 직접 인용한다.

**도구:** `templates/proposal-outline.md`.

**산출물:** 맞춤제안 개요 문서 (1~2페이지 분량).

## Pitfalls (주의사항)

- **미검증 수치 날조 절대 금지**: 기대효과·시장 규모·절감액 등 수치는 반드시 외부 공개 출처와 함께 기재한다. 출처 없으면 쓰지 않는다. 원본 소스에 없는 내용은 쓰지 않는다.
- **외부 공개 정보만 사용**: 콜드아웃리치 이전 단계이므로 내부 정보·인맥 정보에 의존하지 않는다. 웹, 뉴스, 채용 공고, 공시, 케이스스터디만 활용.
- **도입사 = 레퍼런스 레버**: 도입사는 직접 리드가 아니라 경쟁사 접근 시 신뢰도 도구로 활용한다. 도입사에게 다시 영업하지 않는다.
- **BANT 정보 부족 시 '추가 조사' 표시**: 점수를 억지로 채우지 않는다. 정보 공백은 솔직히 기록하고 추가 조사 방향을 제시한다.
- **선별 근거 명시**: "잘 맞을 것 같다"는 직관만으로 리드를 올리지 않는다. 강점-특징 대응 항목이 2개 이상 있어야 한다.
- **제안서 수치는 케이스스터디 기반**: 도입사 성과를 인용할 때 수치를 변형·과장하지 않는다. 원문 그대로 인용하고 URL을 명시한다.
